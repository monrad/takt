# Review: plan — rework

The decomposition is broadly sound, but execution should not start: Task 2 contains an impossible boundary invariant, Task 1's proposed test does not prove that the unset fallback is actually enforced, and Tasks 3/4 introduce fail-open zero budgets that can break the required containment.

- **blocking** :0 — Task 2 requires an impossible GateReview invariant: Task 2 requires every addition to saturate at MaxDuration while also asserting GateReview(bt) > bt without the boundary exception given to Session. For bt == MaxDuration, GateReview must return MaxDuration and therefore cannot be greater than bt. The task and spec must define the saturation-domain exception for GateReview, and its boundary behavior must be tested explicitly.
- **major** :0 — Task 1's fake-reviewer test does not prove the fallback deadline is honored: The test records resolveTimeout(req.Timeout) for an unset request, but exercises cancellation only with a short explicit Timeout. An implementation could record the resolved 15m value while applying a context deadline only for explicit timeouts, and every listed assertion would pass. The seam must observe the deadline on the context actually passed through the fake's work, or otherwise directly test that the resolved fallback is used to construct that context.
- **major** :0 — Tasks 3 and 4 fail open to undersized budgets on read errors: Task 3 says an initial readIndex failure should use a zero Budget and rely on closeWave rereading and surfacing the error; Task 4 similarly maps a finish index-read error to zero commands. This contradicts A2.2's requirement that the outer timeout use the matching binary cap. If a later read succeeds or observes changed bytes, real work can run under Floor or Verify(per, 0). Parse once and thread the value where possible, or propagate the first error instead of emitting/running work, with error-path tests.
